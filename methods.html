How the examples are checked

Original sample data, explicit rules, and reproducible results make the workflows inspectable.

The known-answer sales example

The source contains 14 fictional records. Data record 5 exactly repeats record 4. The prepared set has 13 lines. The week starts October 26, 2026 and ends before November 2. Eligible status is Shipped. This leaves nine lines, eight distinct orders, 26 units, RM286.60 gross, RM19.00 discounts, and RM267.60 net.

The line arithmetic is checked independently in JavaScript and in the exported workbook's calculation engine. A quantity edit and a date-window edit are exercised and restored. The workbook is rendered for layout review, and identifiers are inspected as text in the exported file. A byte-identical copy was also opened in Excel for Windows: changing Orders G6 from 2 to 3 recalculated net sales to RM280.10 and units to 27 while distinct orders remained eight. The public workbook keeps the original quantity and RM267.60 result. Download the expected results.

The browser tools

Parser checks cover quoted commas, escaped quotes, multiline records, byte-order marks, semicolons, tabs, malformed quotes, mismatched widths, and size limits. Comparison checks cover changed values, column order, repeated keys, blanks, and exact matching. Date checks cover ambiguity, fixed conventions, leap days, invalid dates, and the supported year range. Sales-report checks reconcile every source record and verify exact cent arithmetic, known duplicates, conflicting line keys, invalid amounts, zero-price lines, and date boundaries. The comparison export retains field names and every repeated source record.

The tool application uses bundled local JavaScript and reads file text in browser memory, with no file-upload endpoint. The live hosting service injects Cloudflare Web Analytics; the earlier claim that the pages had no analytics was incorrect and was corrected on November 13, 2026. Read the current disclosure. Review downloads apply an apostrophe to formula-like fields and retain unresolved findings. The original input file is not modified.

AI practice cases and Power Query

The AI library uses authored fictional scenarios and answer keys, not recorded model outputs, customer testimonials or product rankings. The Power Query page provides the exact M function and a self-test containing three fictional input cases. On November 13, 2026, all three M files passed syntax parsing with Microsoft’s @microsoft/powerquery-parser 5.0.0. This checks the language syntax, not function evaluation. Native Power Query execution and local-file refresh were not completed during this update; run the supplied self-test and refresh checks in your Excel version before relying on the query. Automated JavaScript checks verify the sample’s expected results independently.

What the verification does not establish

Formula-engine checks do not prove every menu path, Power Query step, or Excel version behaves identically. Power Query instructions refer to Microsoft's documentation and require checking in your installed version. These examples do not measure real-world AI speed or accuracy. The method-comparison log is blank for your own observed measurements.

Corrections and changes

Use the feedback page to report the URL, a fictional reproduction, expected outcome, and observed outcome. Reports use a public issue tracker; do not include private customer exports. A meaningful change should update the affected guide, its sample results, and the associated checks together.
