Build a repeatable CSV cleanup in Power Query

Build a reusable Power Query function with downloadable M code, a second-source check, and explicit known answers.

The AI ExplainerPublished November 4, 2026 · Updated November 13, 20264 min readExample & verification method

What this query does

This walkthrough supplies the actual M code for a reusable import. It reads this site's 11-column fictional order export, preserves identifiers as text, converts day-first dates and non-negative decimal RM amounts, and adds gross and net line values. It deliberately supports a narrower amount format than the browser reconciler: no comma thousands separators, refunds or accounting parentheses.

The existing sales workbook contains prepared data and formulas, with no embedded query. The files below are plain-text M code to put into Power Query.

Create the reusable function

  1. In Excel desktop, open a blank workbook. Use Data → Get Data → From Other Sources → Blank Query. Command labels vary by version.
  2. Open Advanced Editor. Replace its contents with the text of order-cleanup-function.pq, then select Done.
  3. Name this query exactly OrderCleanup. It returns a function with a CSV-text argument and an optional exact-repeat-removal argument.
  4. Keep the function as a connection rather than trying to load the function itself as a worksheet table.

The code uses explicit dd/MM/yyyy parsing and leaves IDs as the original CSV strings. Schema changes stop the query rather than supplying missing columns as null. Invalid quantities and amounts remain errors; do not replace errors with zero.

Exact repeat removal is off by default. For this fictional source only, the repeated record is documented as accidental. The comparison uses all 11 original columns before type conversion, so a genuine second line within an order remains.

Connect a local source and refresh deliberately

  1. Create another Blank Query and paste order-cleanup-file.pq. Change SourcePath to a working copy of orders-messy.csv on your device.
  2. For the documented sample only, set RemoveConfirmedExactRepeats = true. Keep false for unfamiliar data until its duplicate rule is reviewed.
  3. Load the result to a worksheet table. Confirm 13 prepared rows, original text IDs, dates and numeric amounts. There are no report-week filters in the cleanup query.
  4. Back up the first working source. Replace its contents with refresh-next-week.csv while keeping the same working filename and schema. Use Refresh All.
  5. Confirm that the actual loaded table now contains two rows, IDs 000201 and 000202, five units and RM85.00 net. Check the reporting window separately if a summary depends on the table.

The downloaded file-connection query has a placeholder path. The self-test validates the transformations independently of that path; a successful self-test does not prove you selected the intended local file.

Expose a changed source instead of hiding it

On a disposable source copy, rename quantity to qty. The schema check should report an error. Restore the header, then change a quantity to a negative or fractional value and verify it remains an error. Try an impossible date and an amount using a comma decimal separator. Restore each case before continuing.

The function is a teaching implementation for this fixed schema, not a universal CSV validator. Inspect malformed or unfamiliar exports with the CSV diagnostic first. It does not decide whether an apparently repeated transaction is legitimate, detect every conflicting business key, or handle returns, tax or currency conversion.

Keep the original file, source convention, duplicate decision and expected results with the workflow. If a later export changes those assumptions, update and recheck the query before using its totals.
