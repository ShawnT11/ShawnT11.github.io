Compare two order exports without silently merging records

Find new, removed, changed, and repeated order keys using two fictional exports, with a complete expected-result table.

The AI ExplainerPublished November 4, 2026 · Updated November 13, 20263 min readExample & verification method

Define what one row represents

Before comparing two lists, decide whether each row is an order, an item within an order, or an event in an order's history. A single order_id works only if each file contains at most one record per order. The two comparison samples are order-level snapshots, with one deliberately repeated key to show why a tool should stop short of merging it.

The result counts are two unchanged, one changed, one only in A, one only in B, and one repeated key. File A has six records, file B has five, and the union contains six distinct keys. These numbers measure different things and should not be substituted for each other.

Understand the matching rules

The comparison is exact and case-sensitive. Spaces remain significant. A six-character key 000101 and the same key followed by one ASCII space (seven characters) are different keys. Values such as 20.0 and 20.00 count as different text even when they represent the same amount. Normalize only after agreeing what differences are harmless for your source.

If a key repeats in either file, the tool reports the group for review, including its row counts. It does not pick the first record, add the amounts, or remove a row. On a line-item export, create a documented composite key such as an order ID plus a line ID, and check that the separator cannot appear in either part. Duplicate composite keys still need investigation.

Use the report as a review queue

The download is a review report, not an updated order ledger. Each result includes the key, classification, counts, and the source records from both files as JSON objects with column names. Repeated-key groups retain every source record in the export; the tool does not select a winner. Expand a repeated group on screen to inspect it. The screen limits the number of displayed records, while the download includes the complete review result within the input limits.

Do not interpret “Only in B” as a sale or “Only in A” as a deletion until you understand the export filters and dates. Snapshots made at different times may include legitimate status changes. Keep source snapshots and the export settings with your reconciliation notes.
