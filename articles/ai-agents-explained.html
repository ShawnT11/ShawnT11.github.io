Where an AI agent needs a stop in an order workflow

Map reading, drafting, editing, and sending to different permissions using a fictional delayed order.

Maintained by ShawnUpdated November 13, 20262 min read

The examples and answer keys on this page are authored teaching material. They are not recorded model outputs or claims about product performance.

A suggested next step is different from an executed action

For this case, an agent is a system that can choose and use tools while working toward a task. The important distinction is what it can change. An assistant that drafts an update needs different access from one that modifies an order or sends the message.

Start with the fictional delayed-order brief ↓

The task is to prepare a customer update using a carrier estimate. It does not authorize compensation, changing delivery details or contacting a different customer.

Give each step an observable boundary

StepRequired capabilityCompletion evidence
Read the estimateRead carrier statusSource and observation time recorded
Draft the updateCreate unsent textDraft matches the brief
Change the addressModify orderStop: outside this task
Send emailContact the customerCorrect recipient, approved draft and explicit send authorization

Write these limits before connecting tools. “Handle the delay” is too ambiguous to establish whether refunds or record changes are allowed.

Prevent retries from creating extra actions

Suppose a send tool times out. The system should inspect the send record before trying again. A timeout does not prove that delivery failed. Repeating the action without checking may send duplicate messages. For a real integration, define a unique operation identifier and a way to reconcile the result.

A webpage or carrier note might contain instructions. Treat them as information about the parcel, not as authority to expand the task. Keep tool permissions narrower than the full power of the user account where possible.

Rehearse with unsent drafts first

Test an ordinary case, an absent estimate, a conflicting order reference and an uncertain send result. An acceptable run stops when it cannot establish the facts or action outcome. This article is a design exercise; no autonomous agent or messaging service was deployed or benchmarked here.
