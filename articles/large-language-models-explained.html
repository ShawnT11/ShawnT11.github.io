Why an LLM can write a fluent but unsupported answer

Trace a visitor-policy question through source text, missing evidence, and a checkable answer.

Maintained by ShawnUpdated November 13, 20262 min read

Fictional practice case. The example prompts and answers are written for the exercise; they are not captured AI responses.

A fluent answer can use the wrong rule

A large language model generates text using learned patterns and the context supplied to it. That makes it useful for explaining and rewriting text, but a convincing sentence alone does not establish which policy applies. Use the fictional policy pack to inspect that difference.

Download the policy pack ↓

The question is: “Can an ordinary visitor enter at 09:00 on 13 November 2026?” P1 says 09:00, but is archived. Current P2 starts ordinary visits at 10:00 and requires a named host. The 08:00 maintenance exception has separate conditions.

An answer should identify its evidence

An authored correct answer is: “Under P2, ordinary visitor access starts at 10:00 and requires a named host, so 09:00 is outside that window. P1 is superseded. The maintenance exception requires an approved maintenance visit and facilities approval.” Each factual part points to a supplied source.

An answer that says 09:00 because P1 was retrieved has selected a real sentence with the wrong status. An answer that grants access because the cafeteria opens at 08:00 confuses two different permissions. Neither failure requires invented words.

Ask for gaps as well as answers

Try a second question: “Can a visitor enter on Sunday?” The pack gives no weekend rule. The acceptable result is that the supplied material does not establish Sunday access. Asking for a confident yes or no would hide the missing information.

Useful prompt fields are the question date, allowed source IDs, document status and required quotation or section reference. Those fields help a reviewer; they cannot guarantee that a model selects the right evidence.

Keep the scope of the exercise clear

This is an authored reasoning case, not an observed failure rate for any model. Product context limits, tools and retrieval features vary. For real access decisions, check the authoritative policy and ask its owner about omissions. Use this pack to practice distinguishing supported, contradicted and unestablished claims.
