What AI changes in a support-ticket workflow

Compare a keyword rule with a proposed AI classifier using six fictional tickets and an answer key.

Maintained by ShawnUpdated November 13, 20262 min read

The examples and answer keys on this page are authored teaching material. They are not recorded model outputs or claims about product performance.

Start with six tickets you can inspect

Artificial intelligence covers systems that infer outputs such as predictions, labels or generated text from inputs. For a small support queue, the useful question is which messages reach the right people. This case separates a simple keyword rule from a proposed classifier without pretending to have benchmarked an AI product.

Six tickets and the intended routing ↓

Hide the expected_queues column before testing a classifier. It is an answer key for this exercise, not an input feature. Every message is fictional.

Trace the rule before replacing it

Consider the rule “route messages containing refund to Refund.” It sends T01 correctly, but also sends T05 to Refund even though the customer explicitly asks for a replacement. It misses the damaged mug in T02. T03 requires both Billing and Delivery; a single-label design loses part of the request.

Give the proposed classifier a fair test

Ask for zero or more queue labels, the source words supporting each label, and Needs clarification when the request is insufficient. Score the routing against the answer key. A plausible explanation cannot compensate for a missed billing issue. Record the exact prompt, product, model if shown, test date and full output.

Six cases reveal particular failures; they cannot estimate production accuracy. A deployment decision needs representative messages, edge cases, workload costs and a review process. Keep real customer information in approved systems.

Choose the smallest useful change

If the queue needs only a reliable refund keyword alert, a corrected rule may be enough. If paraphrases and multiple issues matter, evaluate a classifier. Keep uncertain requests visible for a person. The output of this exercise is a routing test and a decision record, rather than a general claim that AI understands customers.
